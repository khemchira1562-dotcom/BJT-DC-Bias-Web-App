# Reflection — Lab 02

## 1. Frontend / Backend / Template ต่างกันอย่างไร

Frontend คือส่วนที่ผู้ใช้เห็นและโต้ตอบด้วยใน Browser ได้แก่ ฟอร์มกรอกค่า
ปุ่ม Calculate และตารางผลลัพธ์ ซึ่งถูกสร้างจาก HTML + CSS
Backend คือ Flask/Python ที่รับ Request, ตรวจสอบข้อมูล และคำนวณ DC Bias จริง
ส่วน Template (`templates/index.html`) เป็น HTML ต้นแบบที่มีช่องว่างให้ Jinja
เติมค่าจาก Backend ก่อนส่งกลับไป จึงไม่ใช่ไฟล์ที่คำนวณเองและเปิดด้วย `file://` ไม่ได้

## 2. ฟอร์มส่งข้อมูลไปถึง Python ได้อย่างไร

ฟอร์มใช้ `method="post" action="/"` เมื่อกดปุ่ม Browser จะรวมค่าของ input
ทั้ง 7 ช่องเป็น body แบบ `application/x-www-form-urlencoded` แล้วส่ง HTTP POST
ไปยัง Flask route `submit()` ซึ่งอ่านค่าด้วย `request.form`, แปลงหน่วย kΩ
เป็น Ω แล้วเรียก `calculate()` จาก `dc_bias.py` จากนั้น `render_template()`
สร้าง HTML ใหม่ที่มีผลลัพธ์ส่งกลับไป (HTTP 200) หากค่าผิดจะได้ HTTP 400
พร้อมข้อความ error แทน

## 3. ถ้าแก้สมการใน `dc_bias.py` ต้องแก้ HTML ด้วยหรือไม่ เพราะอะไร

ไม่ต้องครับ เพราะ Template ไม่มีสมการฟิสิกส์เลย มีเพียงการแสดงค่า เช่น
`{{ result.vce|fmt }} V` ถ้าเปลี่ยนวิธีคำนวณหรือเปลี่ยนค่า `VCE_SAT`
ตัวเลขที่แสดงจะเปลี่ยนตามเองโดยไม่ต้องแตะ HTML ยกเว้นกรณีเพิ่มปริมาณใหม่
ที่ยังไม่มีช่องแสดงผล เช่น อยากโชว์ power dissipation ก็ต้องเพิ่มแถวในตาราง
การแยกแบบนี้ทำให้ทดสอบสมการได้โดยไม่ต้องเปิด Browser และลดโอกาสแก้สูตร
แล้วลืมแก้ฝั่งหน้าเว็บ

## 4. ทำไมผลนอก Active Region จึงต้องมี Warning

เพราะสมการที่ใช้ตั้งอยู่บนสมมติฐาน Forward-Active คือ BE ไบอัสตรงและ
BC ไบอัสกลับ ถ้าอยู่นอกช่วงนี้สมการจะไม่อธิบายพฤติกรรมจริง เช่น ใน Cutoff
สมการอาจให้กระแสติดลบ หรือใน Saturation ค่า VCE ที่คำนวณได้อาจติดลบ
ซึ่งเป็นไปไม่ได้ในวงจรจริง ถ้าแสดงตัวเลขออกไปเฉย ๆ ผู้ใช้อาจเข้าใจผิดว่า
เป็นผลที่เชื่อถือได้ ผมจึงให้กรณี Cutoff แสดงกระแสเป็นศูนย์และแจ้งว่า
Forward-Active ใช้ไม่ได้ ส่วน Saturation ยังแสดงค่าตามสมการแต่มี warning
กำกับว่าไม่น่าเชื่อถือ

## 5. ปัญหาที่เจอระหว่างทำ Lab และวิธีแก้

- **Agent มองไม่เห็น `python`/`git`** เพราะ background server ของ OpenCode
  ถูกเปิดค้างไว้ก่อนติดตั้งโปรแกรม จึงเรียกด้วย path เต็มและ restart service
- **หน่วย kΩ กับ Ω** เสี่ยงทำให้ผลผิด 1000 เท่า แก้โดยแปลงหน่วยที่
  `parse_inputs()` จุดเดียวและเขียน test ยืนยันว่า R1 = 100 kΩ ให้ RTH ≈ 18 kΩ
- **Test ล้มเพราะ tolerance แน่นเกิน** `assertAlmostEqual(places=4)` ไม่ผ่าน
  ค่า 1.2421567 กับ 1.2421 แก้เป็น `delta=0.001` ให้เหมาะกับค่าที่ปัดแล้ว
- **Test เข้าใจผิดว่าเปลี่ยน VCC แล้วมีแค่ VC ที่เปลี่ยน** จริง ๆ แล้ว VTH
  และ IB เปลี่ยนด้วย จึงเปลี่ยนไปทดสอบด้วยการแก้ RC แทน
- **push จาก CLI ไม่ได้** เพราะ token อยู่กับ GitHub Desktop จึง push
  ผ่าน GitHub Desktop
